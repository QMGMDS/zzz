# 软复核自检清单

软复核处理硬门禁管不到的**语义条目**——机器判不准、需 AI 理解后判断的事项。用户说"跑一次软复核"时，对照本清单逐条过本次改动的相关代码，出报告（含已过/待修项），由人决定是否接受。

写完一段代码，在四个护栏领域自检：

- [ ] 命名：类名是否说明职责、避开 `Manager`/`Script` 滥用？字段是否 `_`/`s_`/常量大驼峰？异步方法带 `Async`？回调带 `On` 前缀？
- [ ] 注释：是否用 ` - ` 而非 `——`？是否提及了脚本名？公有方法是否三行 XML？
- [ ] Inspector：字段是否 `[SerializeField] private` + `[Tooltip]`？有无 `public` 字段裸露？是否单一所有者？运行时状态是否被塞进 SO？
- [ ] 生命周期：`Update` 里有无 `Find*`/`GetComponent`？事件订阅是否成对退订？`CTS` 是否在 `OnDestroy` 取消释放？

> 命名/Inspector/生命周期里有些条目已由硬门禁机械判定（R1/R3/R5/R7 等），软复核不重复机器已管的部分，只补机器判不准的语义：事件退订是否成对、CTS 是否释放、运行时状态是否塞 SO、字段是否双所有者、注释是否提及脚本名、注释是否简明。
