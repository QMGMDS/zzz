## 玩家角色控制器设计

`_Script/Player` 玩家角色控制器相关的所有脚本，所有的一切都是为了玩家角色控制器所服务。

目前共包含三个模块 :

- **数据中枢模块**
- **玩家输入模块**
- **角色状态模块**

一个主脚本 :

`PlayerController.cs` 负责统一装配角色控制器所需要的所有核心系统并注入依赖，作为公共 Mono 协调各系统的执行先后顺序。

### 数据中枢模块✅

采用黑板模式，玩家角色持有属于自己的运行时数据黑板，作为玩家角色各系统交互的唯一途径。

最大的好处即 : 各模块之间无需相互调用，谁要数据就从黑板中拿取即可。

如 : 玩家输入模块将玩家输入意图写在黑板上，角色状态模块读取黑板上的意图数据做出相应反应，而无需调用或请求玩家输入模块。

当前存储的运行时数据 (每逻辑帧自动清理角色意图数据) :

- 输入板块 (输入处理器负责写入)

    1. 移动意图
    2. 闪避意图


- 逻辑状态板块 (状态逻辑层负责写入)

    1. 玩家角色状态机当前所处的逻辑状态

- 动画信息板块 (动画表现层负责写入)

    1. 玩家角色当前动画播放进度

### 玩家输入模块✅

采用管道-过滤器模式，将玩家输入数据的提纯分为三个阶段 :

- **原始输入数据**
- **后处理输入数据**
- **角色意图数据**

对于每逻辑帧 :
1. 输入数据采集员从输入源中采集得到原始输入数据
2. 输入采集员对原始输入数据进行后处理 (防抖、延时等手感处理)，得到后处理输入数据
3. 输入处理器将各后处理数据进行角色意图翻译，翻译后的意图写入数据中枢模块 (黑板) 中

为细分不同处理器的具体职责，所有子处理器统一由主处理器工厂实例化并注入依赖。

### 角色状态模块✅

角色状态模块分为三个层级 :

- **状态逻辑层** : 负责纯逻辑状态之间的切换
- **动画表现层** : 负责纯动画播放的视觉表现
- **物理移动层** : 负责实际场景中的位移旋转

#### 状态逻辑层

最终目标 : 状态灵活切换的前提下，让不同状态间不必认识对方。

核心思路 : 类 HFSM + 拦截器 + 豁免机制(可选拓展)

将玩家角色的所有状态划分族 :

| 分类       | 状态成员                                           |
| ---------- | -------------------------------------------------- |
| 静止族成员 | Idle、IdleAFK、Stop                                |
| 行走族成员 | WalkStart、WalkLoop                                |
| 奔跑族成员 | RunStart、RunLoop、RunTurn                         |
| 闪避族成员 | EvadeFront、EvadeFrontEnd、EvadeBack、EvadeBackEnd |

核心约束 :
1. 跨族范围的状态切换必须通过对应拦截器规范切换通道
2. 不同族之间的状态成员完全不认识对方的存在
3. 族内部的状态成员允许认识对方并显示切换
