## 玩家角色控制器设计

`_Script/Player` 玩家角色控制器相关的所有脚本，所有的一切都是为了玩家角色控制器所服务。

目前共包含三个模块 :

- **数据中枢模块**
- **玩家输入模块**
- **角色状态模块**

一个主脚本 :

`PlayerController.cs` 负责统一装配角色控制器所需要的所有核心系统并注入依赖，作为公共 Mono 协调各系统的执行先后顺序。

每帧按固定管线推动，确保各模块拿到新鲜数据 :

```
Update:
  InputCollector.Update()  ── 采样 + 后处理（防抖 + BufferTimer）
    ↓
  InputMainProcessor.UpdateInputProcessors()  ── 意图翻译 → 写入黑板
    ↓
  GroupStateMachine.LogicUpdate()  ── 族长状态机逻辑更新（含拦截器检查+族内转移）
    ↓
  AnimationDriver.Update()  ── 下达动画指令
    ↓
  PlayerMotor.ApplyRotation()  ── 旋转更新，使 Animator 计算根运动时基于新朝向

  [Animator 自动更新骨骼，产出本帧根位移]

OnAnimatorMove:
  PlayerMotor.ApplyMove()  ── 位移更新

LateUpdate:
  AnimationDriver.SyncAnimProgress()  ── 动画进度回写黑板
    ↓
  PlayerBrain.ResetInputBrain()  ── 清除意图标记
```

### 数据中枢模块✅

采用黑板模式，玩家角色持有属于自己的运行时数据黑板，作为玩家角色各系统交互的唯一途径。

最大的好处即 : 各模块之间无需相互调用，谁要数据就从黑板中拿取即可。

如 : 玩家输入模块将玩家输入意图写在黑板上，角色状态模块读取黑板上的意图数据做出相应反应，而无需调用或请求玩家输入模块。

当前存储的运行时数据 (每逻辑帧自动清理角色意图数据) :

- 摄像机板块 (PlayerController 负责写入)

    1. 主摄像机 Transform 引用，用于计算相对玩家角色坐标系的输入方向。

- 输入板块 (输入处理器负责写入)

    1. 本帧是否按下攻击
    2. 是否持续按下攻击
    3. 本帧是否按下闪避
    4. 本帧是否移动
    5. 本帧移动输入 Vector2
    6. 本帧角色移动方向 (移动输入联系摄像机后的朝向)
    7. 上一帧角色移动方向 (移动输入联系摄像机后的朝向)
    8. 本帧是否发生输入方向偏转 (RunTurn 信号)

- 逻辑状态板块 (状态逻辑层负责写入)

    1. 当前激活的状态节点

- 动画信息板块 (动画表现层负责写入)

    1. 当前状态动画归一化时间 0~1
    2. 当前状态动画是否播放完毕

### 玩家输入模块✅

采用管道-过滤器模式，将玩家输入数据的提纯分为三个阶段 :

- **原始输入数据**
- **后处理输入数据**
- **角色意图数据**

对于每逻辑帧 :
1. 输入数据采集员从输入源中采集得到原始输入数据
2. 输入采集员对原始输入数据进行后处理 (防抖、延时等手感处理)，得到后处理输入数据
3. 输入处理器将各后处理数据进行角色意图翻译，翻译后的意图写入数据中枢模块 (黑板) 中

为细分不同处理器的具体职责，所有子处理器统一由主处理器工厂实例化并注入依赖。

### 角色状态模块✅

角色状态模块分为三个层级 :

- **状态逻辑层** : 负责纯逻辑状态之间的切换
- **动画表现层** : 负责纯动画播放的视觉表现
- **物理移动层** : 负责实际场景中的位移旋转

#### 状态逻辑层

**最终目标 : 数据驱动状态切换。**

核心思路 :

状态之间的切换需要三个信息 :
- 当前是什么状态。
- 需要满足的切换条件 (当前状态动画是否播放完成、是否按下攻击键)。
- 切换的目标状态。

1. 状态节点化，作为纯数据 SO 文件。保存该状态要播放的动画等等信息。
2. 状态族包裹族内节点，作为记载族内切换路径的 SO 文件。
3. 拦截器作为记载不同族切换路径的 SO 文件。

如此一来，状态节点之间可以自由排列组合。通过编辑 SO 文件灵活修改状态的切换逻辑，哪怕不同角色的状态组合完全不同，也同样可以共用这一套 **节点-规则** 状态系统。

核心约束 :

1. 由拦截器定义跨族状态之间的切换。
2. 由族管理器定义同族状态之间的切换。

拓展 :

- 添加了状态的打断窗口，打断窗口内才允许该状态被打断。(该机制仅作用于同族状态之间)
- 特殊状态如需自定义切换跳转逻辑 (如相同状态节点下根据玩家不同输入切入不同节点分支)，可自定编写行为插件脚本，绑定在目标状态节点 SO 文件上。

以安比为例，该角色的所有状态划分族 :

| 分类       | 状态节点                                           |
| ---------- | -------------------------------------------------- |
| 静止族 | Idle、IdleAFK、Stop                                |
| 行走族 | WalkStart、WalkLoop                                |
| 奔跑族 | RunStart、RunLoop、RunTurn                         |
| 闪避族 | EvadeFront、EvadeFrontEnd、EvadeBack、EvadeBackEnd |
| 攻击族 | Attack_1、Attack_1_End、Attack_2、Attack_2_End、Attack_3、Attack_3_End、Attack_4、Attack_4_Normal_End、Attack_4、Attack_4_Prefect_End |

#### 动画表现层✅

**最终目标 : 自行维护动画播放。**

AnimationDriver 动画驱动器通过读取黑板上当前状态，自行播放对应的动画，并回写当前动画的播放进度。

动画驱动器被拆分成两个部分 :

1. 根据黑板信息下达更新当前动画的指令。
2. 读取当前动画进度，回写黑板。

#### 物理移动层✅

**最终目标 : 不丢失动画根运动曲线带来角色位移的自然感，同时代码具有一定自主操纵权**

PlayerMotor 玩家移动器被拆分成两个部分 :

1. 根据黑板上玩家输入信息，和自定义配置信息，应用角色物体旋转。
2. 根据动画根运动数据信息，和自定义配置信息，应用角色物体位移。
